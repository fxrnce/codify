# Codify mobile admin handoff

The administrator interface belongs inside the Expo mobile app. The older
`admin/` web project remains only as historical reference and is not a deployment
target.

## Current implementation

- `app/(tabs)/admin.tsx` is visible only when `/api/me` returns `role: "ADMIN"`.
- `app/admin/reports.tsx` and `app/admin/report/[id].tsx` support report search,
  status review, responses to users, optimistic locking, and report audit history.
- `app/admin/products.tsx` and `app/admin/product/[id].tsx` support catalog search,
  adding, editing, archiving, nutrition, ingredients, allergens, FDA references,
  and optimistic locking.
- `app/admin/advisories.tsx` and `app/admin/advisory/[id].tsx` support advisory
  search, creation, editing, activation, source URLs, optimistic locking, and
  advisory audit history.
- `contexts/AdminAccessContext.tsx` checks the server role and network state.
- Admin writes are disabled offline. Regular users can still queue product reports.
- The backend checks the database role on every `/api/admin/*` request and records
  changes in `AdminAuditLog`.
- Render startup runs migrations and starts the API without reseeding catalog data.

The migration is in
`backend/prisma/migrations/20260914090000_add_admin_workflow/migration.sql`.

## Administrator setup

An account must first sign up and verify its email in the mobile app. Then run:

```powershell
cd backend
npm run admin:set -- johnlaurence0922@gmail.com ADMIN
```

The role is never assigned from the client.

`johnlaurence0922@gmail.com` was assigned the `ADMIN` role on 2026-09-14.

## Verification

Run these before committing:

```powershell
npm run lint
npm run typecheck
npx expo install --check
cd backend
npm run prisma:validate
npm run typecheck
npm run build
npm run test:admin
```

Do not commit or push unless the user asks in the current conversation. Preserve
all unrelated working-tree changes.
